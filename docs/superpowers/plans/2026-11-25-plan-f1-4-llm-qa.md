# Plan F1.4: LLM gateway + topic Q&A for tử vi (paid credits, 2 follow-ups, 3 free chats/day, SSE, safety filters)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `reading-tuvi` answers a user's question about one topic of their own chart in Lão Thiên Cơ's voice. The answer is grounded only in approved knowledge records chosen from the chart. It is produced by a free-first LLM gateway (Fake, then Groq → Gemini → optional paid tier), filtered for safety, and streamed over SSE. A paid question costs one credit from identity-svc before generation and comes with 2 follow-ups. When generation fails, the question is retried for 24 h and the credit is then refunded. Free chats are capped at 3/day per person and per chart, and they never use the paid tier.

**Architecture:** The gateway is a Java library inside `reading-tuvi`: application class `LlmGateway` over `LlmProviderPort` adapters. There is no new service and no Rust. Spec §6.4 calls it "thư viện trong reading-svc", and its only callers are the Java reading deployments (`reading-astro` reuses the same image in F2). A separate Rust service would add a network hop, a container on a 2-core machine, and a second copy of the quota state. All Q&A runs inside `reading-tuvi`, in this order:
- The web BFF forwards the user's session bearer with the internal token.
- `reading-tuvi` resolves the subject and the encrypted-at-rest chart profile through identity-svc (`GET /me`, `GET /me/profile`).
- It computes the chart through chart-svc (existing `ChartPort`).
- It charges through `POST /internal/credits/consume` (keyed by `reading_id`).
- It builds the context deterministically from the chart: topic → palaces → the existing `ReadingPlan` lookup chains → approved snippets.
- It calls the gateway, filters the answer, stores it encrypted, and streams it.

A scheduled job retries queued paid questions and refunds them through `POST /internal/credits/refund` after 24 h. Semantic chunks and pgvector are not built in this plan (see Notes). Backend only: spec §9 lists F1.4 as gateway + Q&A + credits + SSE + filters. The Q&A screens, ink-bleed streaming effect and history page land in **F1.5b**, so `services/web` is untouched.

**Tech Stack:** Java 21, Spring Boot (parent version), Spring MVC `SseEmitter`, `RestClient`, JDBC + Flyway + Postgres, JCA AES-256-GCM, Jackson, JDK `com.sun.net.httpserver.HttpServer` (LLM stub in tests), Testcontainers (Postgres), ArchUnit, JaCoCo.

**Spec:** `docs/superpowers/specs/2026-11-24-fortune-platform-design.md`: §1–§2 (G2 topic Q&A grounded in the corpus; anti-goals: no self-computed chart, no invention, LLM cost of the free part must not scale with traffic, no leaking birth data/chat), §3 + §5.3 (free LLM, **never Claude API at runtime**), §5.6 (no citations shown), §6.4 (Chat AI, LLM gateway: ordered providers, quota tracking, failover, "hôm nay hết lượt"), §7 (no name/email to LLM, encrypted chat, 90-day chat retention, no full birth in logs), §8, §9 (F1.4 scope), §11 (free-tier terms check; gateway supports the paid endpoint of the same API), §12.3 (small paid fallback, monthly budget, 80% alert), §13.2 (1 credit = 1 question + 2 follow-ups on one topic; failure after 24 h retry → automatic credit refund), §14.1 (YEAR pass daily cap 30, enforced by identity), §14.2 (Lão Thiên Cơ: "ta"/"con"), §14.4 (streamed answer), §15 (no medical/legal/financial/gambling advice, no fear-selling, no "giải hạn/cúng/bùa", AI-content label, anonymise before cross-border transfer). Repo rules: `CLAUDE.md`, `.claude/skills/java-service-conventions/SKILL.md`. Patterns to copy: `services/reading-tuvi` (`ReadingService`, `ReadingExceptionHandler`, `ContractTest`, `ReadingFlowIT`), `services/identity-svc` (`AesGcmBirthCipherAdapter`, `@Transactional` in application, `NoPiiInLogsIT`), `services/payment-svc` (`SepayReconcileJob` scheduled executor, `IdentityCreditsAdapter` RestClient with timeouts).

## Review Focus

1. **The same question is submitted twice.** This covers a double click, a BFF retry after a timeout, and two tabs with the same `reading_id`. Expected: one charge, one answer, the second call replays it. A concurrent duplicate gets 409 `reading_in_progress`, never a second consume. Tests in Task 5: `same_reading_id_twice_charges_once`, `concurrent_same_reading_id_one_generation`.
2. **Hostile or spoofed questions.**
   - Inputs: Vietnamese and English injection phrasing, a question containing `>>>` / `<<<` or "CÂU HỎI:", requests to reveal the instructions.
   - Expected: refused before charging. If a model still echoes prompt markers, `AnswerFilter` rejects the answer.
   - Ordinary questions must pass: "vấn đề tiền bạc năm nay", "con cái của tôi", "có nên đổi việc".
   - Tests in Task 3: `injection_phrasings_refused`, `ordinary_questions_pass`, `leak_markers_rejected`.
3. **Provider rate limits.**
   - A 429 with `Retry-After: 20` (per-minute limit) skips that provider for 20 s only. A 429 without `Retry-After` skips it until the next UTC midnight.
   - Daily limit reached → skip. All providers out → a paid question is queued and a free chat gets the "busy" message.
   - A free chat never reaches the `paid` provider.
   - Tests in Task 1: `rate_limit_with_retry_after_is_short`, `free_tier_never_uses_paid`, `paid_budget_exhausted_skips_paid`.
4. **Retry/refund edges.**
   - Cases: a process crash leaves a reading `PENDING`; identity is down when the refund is due; the 24 h boundary is exact; identity says "never charged" (404); identity times out during consume.
   - Expected: every charged reading ends `ANSWERED` or `REFUNDED`, with exactly one refund call that succeeded.
   - Tests in Task 6: `stuck_pending_is_requeued`, `refund_retried_until_identity_answers`, `answer_at_23h59_no_refund`, `refund_404_marks_failed`, `consume_timeout_compensated`.
5. **Personal data reaching the LLM or logs.**
   - Inputs: a question containing a phone number, an email or a dd/mm/yyyy date; a profile label like "Nguyễn Văn A".
   - Expected: the captured prompt contains none of them, nor the birth string, nor any UUID. Logs of a full paid flow contain none of question, answer, birth, bearer.
   - Tests: `prompt_contains_no_personal_data` (Task 4) and `NoPiiInLogsIT` (Task 5).

### Task 3: Safety: question guard, PII scrubber, answer filter, Q&A frames

**Files:**

  - `knowledge/tuvi/frames.vi.jsonl`: add 12 frames.
  - `KnowledgeCoverageTest` only if it pins the frame count.
- Test: `domain/qa/{QuestionNormalizerTest, PiiScrubberTest, QuestionGuardTest, AnswerFilterTest}.java`; existing `KnowledgeQualityTest` must still pass with the new frames

**Interfaces:**
- Produces: `enum QaTopic {TinhDuyen, SuNghiep, TaiLoc, SucKhoe, GiaDao, VanNam}` with `labelVi()` (labels in Global Constraints).
- Produces: `QuestionNormalizer.normalize(String) -> String`: NFC, trim, collapse whitespace, `toLowerCase(Locale.ROOT)`, strip trailing `?.!…`. Used for the cache key and keyword matching.
- Produces: `PiiScrubber.scrub(String) -> String`. It replaces each of these with `[đã ẩn]`:
  - emails
  - phone numbers `(\+?84|0)[\s.-]?\d(?:[\s.-]?\d){7,9}`
  - dates `\d{1,2}[/.-]\d{1,2}[/.-]\d{2,4}`
  - any run of ≥ 6 digits
- Produces: `QuestionGuard.check(String raw) -> GuardResult`, a sealed type:
  - `Ok(String sanitized)`: control chars except `\n` removed; `<<<`, `>>>` and backticks removed; scrubbed.
  - `Invalid(String field)`: fewer than 5 or more than 500 chars after trim → field `question`.
  - `Refused(RefusalReason reason)` with `enum RefusalReason {MEDICAL, LEGAL, FINANCE, GAMBLING, DEATH, SELF_HARM, INJECTION, OFF_TOPIC, INSUFFICIENT}`. Matching is on the normalized text with phrase or word-boundary rules (`(?<!\p{L})…(?!\p{L})`) so `vấn đề` is never gambling. The builder writes the full lists, which must include at least:
    - MEDICAL: `thuốc`, `chữa bệnh`, `điều trị`, `phẫu thuật`, `xét nghiệm`, `bác sĩ`, `kê đơn`
    - LEGAL: `kiện`, `luật sư`, `ra tòa`, `tranh chấp đất`
    - FINANCE: `cổ phiếu`, `chứng khoán`, `crypto`, `bitcoin`, `tiền ảo`, `mua vàng`, `vay`, `lãi suất`, `đầu tư vào`
    - GAMBLING: `lô đề`, `đánh đề`, `số đề`, `xổ số`, `cá độ`, `cá cược`, `casino`, `đánh bài`, `con số may mắn`
    - DEATH: `khi nào chết`, `sống được bao lâu`, `tuổi thọ`, `qua đời`
    - SELF_HARM: `tự tử`, `tự sát`, `muốn chết`, `kết liễu`
    - INJECTION: `bỏ qua (mọi|các|tất cả|những) (hướng dẫn|chỉ dẫn|quy tắc)`, `ignore (all|previous|the above)`, `system prompt`, `lời nhắc hệ thống`, `tiết lộ (prompt|hướng dẫn)`, `đóng vai`, `act as`, `developer mode`, `bạn là một`, `CÂU HỎI:`, `TƯ LIỆU:`

    Evaluation order: SELF_HARM first, then the rest in enum order.
- Produces: `Sentinel` constants `NGOAI_PHAM_VI` (→ `OFF_TOPIC`) and `KHONG_DU_TU_LIEU` (→ `INSUFFICIENT`), and `Sentinel.detect(String answer) -> Optional<RefusalReason>` (the answer's trimmed text starts with or equals the sentinel).
- Produces: `AnswerFilter.check(String answer, AnswerLimits limits) -> FilterResult`, a sealed type `Pass(String cleaned) | Reject(String rule)`.
  - **Cleaning first:** strip markdown `#` headings, `**`, `__`, and citation brackets `\[\d+\]`.
  - **Rules** (`rule` names):
